5. Por qué Algunas Columnas no Tienen Variable PHP Equivalente

Las columnas sin variable PHP equivalente tienen ese “vacío” por razones técnicas específicas. Se agrupan en 4 categorías:

5.1 Columnas usadas solo en cláusulas WHERE / filtros

Aparecen en el SQL pero su valor nunca se guarda en PHP — solo sirven para filtrar:

// body_type_fk nunca se asigna a una variable, solo filtra
$filter = ' body_type_fk=2 AND instituciones.private =0';
// type_institucion solo aparece en el WHERE
$sql = 'SELECT ... FROM metages_recurso_cat WHERE type_institucion=1';
// Tipo solo filtra en el WHERE
$sql = 'SELECT ... FROM metages_disciplina WHERE Tipo=\'coleccion\'';

Estas columnas (body_type_fk, private, type_institucion, Tipo, type_curso_type_fk=221) son constantes de filtrado hardcodeadas.

5.2 Columnas usadas solo como claves de JOIN

Son el “pegamento” entre tablas. PHP nunca necesita su valor, solo la base de datos los usa internamente para relacionar filas:

// address_fk, person_fk, body_fk — solo aparecen en ON de JOINs
$join = ' LEFT JOIN metages_address ON instituciones.address_fk = address_id';
$join = ' LEFT JOIN metages_personinbody ON body_id = metages_personinbody.body_fk';
$join = ' LEFT JOIN metages_person ON metages_personinbody.person_fk = person_id';

Las columnas address_fk, person_fk, body_fk, proy_fk, recurso_fk, child_body_fk, parent_body_fk, iso_country_fk, ext_cat_fk, iso_639_1_fk — todas son foreign keys que solo viven en el SQL.

5.3 Columnas usadas solo en escritura (INSERT/UPDATE) desde forms_callbacks.php

Los datos del POST van directamente al SQL sin una variable PHP intermedia con nombre propio:

// El valor de cuest_phone se inserta en la columna telephone,
// pero "telephone" nunca se lee de vuelta en una variable PHP
$sql = $wpdb->prepare('INSERT INTO metages_communication SET 
    `telephone`=%s, 
    `email`=%s', $mid['cuest_phone'], $mid['cuest_email']);

Las columnas telephone, email, keyword_standard, keyword_std_def, version_software, url_map, two_char_code, full_country_name — se escriben pero nunca se leen en ningún template de frontend.

5.4 Primary keys usadas en variables genéricas temporales

Las PKs sí se usan en PHP, pero en variables genéricas como $body_id, $address_id, $person_id — no se incluyen como “equivalentes” porque son variables de control de flujo, no de presentación:

// Se captura el ID solo para usarlo en el siguiente INSERT
if ($wpdb->query($sql))
    $body_id = $wpdb->insert_id;  // variable temporal, no de presentación

En resumen: si una columna no tiene variable PHP equivalente, es porque el código PHP nunca necesita mostrar o manipular ese valor — solo lo usa como filtro, pegamento de JOIN, o destino de escritura. El patrón general es:

Rol de la columna ¿Tiene variable PHP? ¿Por qué?
Se muestra en frontend ✅ Se asigna a $variable para renderizar en HTML
Filtra en WHERE con valor fijo ❌ Está hardcodeada en el string SQL
Foreign key en JOIN ❌ Solo la DB la necesita para relacionar filas
Se escribe desde formulario ❌ Va del $_POST directo al INSERT, sin variable intermedia
Primary key tras INSERT ⚠️ Se usa en variable genérica temporal ($body_id)

6. Origen del Mapeo Variable → Columna

El mapeo entre variables PHP y columnas de metages se establece de tres formas:

  1. Alias SQL directos — La consulta SQL define alias: citation AS institucion, address_line_1 AS direccion, extension AS link_web_es, etc. El código PHP luego accede vía $resultado->institucion.

  2. Acceso directo a columna — Sin alias, se accede directamente: $term->region, $term->recurso_cat_id, $taller->Nombre.

  3. Variables POST de cuestionarios → Columnas de INSERT — En forms_callbacks.php, las variables $mid['cuest_*'] se mapean a columnas mediante sentencias INSERT INTO preparadas.

Important

No existe un ORM ni capa de abstracción. Todas las queries son SQL directo concatenado con $wpdb->prepare() o strings literales. El mapeo es implícito y se define en cada archivo de forma independiente.
